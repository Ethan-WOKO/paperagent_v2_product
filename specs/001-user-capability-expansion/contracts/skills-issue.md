## Installation format (US1, 2026-09-09)
- File picker accepts SKILL.md and optional skill.yaml together. Browser decodes strict UTF-8 and sends JSON `{name?, markdown:{filename,content}, metadata?:{filename,content}}` to POST /api/v1/skills. No multipart spool, archive extraction, filesystem installation, remote fetch or script execution. Request body is capped at 512 KiB before JSON parsing (including escaped JSON); decoded Markdown is capped at 64 KiB and separate YAML at 16 KiB. At most 100 installations per owner; owner lock serializes quota/name checks.
- YAML frontmatter / skill.yaml accept only name, description, allowed_tools or allowed-tools. Safe YAML rejects duplicate keys, custom object tags, excessive nesting and collection aliases. Same fields in both sources must agree; conflicting declarations are rejected. Do not use both allowed-tools spellings. Explicit form name overrides YAML name; absent name falls back to first Markdown H1. Empty bodies and path-like names are rejected. Same-owner normalized names and registry names/IDs conflict; different users can install the same name. The complete prompt must also fit the existing ReAct contract's 32,000 Unicode-code-point limit, in addition to the 64 KiB file limit; unsupported files fail installation, not a later task submission.
- Missing tool declaration freezes the safe read-only defaults `list_project_files`, `read_project_file`, `search_knowledge`. Explicit [] freezes deny-all. A list or whitespace-separated tool names is accepted, up to 32 unique names matching `^[a-z][a-z0-9_]{0,63}$`, consistent with the existing ReAct submission schema; no uppercase aliases, dots, hyphens, wildcards, command arguments or paths. These are restrictions only: Main's runtime policy intersects them with current availability and owner/scope permissions. Detail shows the effective frozen declaration.
- GET list/detail and PUT enablement/DELETE use authenticated ownership. New opaque `user-<UUID>` IDs never replace registry IDs. Registry skills remain available, retain existing enablement behavior and cannot be uninstalled. New installations use database-owned enabled state. General Settings Save omits disabledSkills to avoid stale overwrites.
- Both existing conversation selectors use the same list and resolve service. New requests with a disabled/deleted/foreign skill fail. Existing ReAct tasks retain frozen prompt/tool snapshots; invocation-time availability checking is owned by Main.

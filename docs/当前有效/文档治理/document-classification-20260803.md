# 文档分类与治理索引

更新时间：2026-08-03

## 1. 分类规则

| 分类 | 含义 | 使用方式 |
| --- | --- | --- |
| 当前有效 | 当前仍约束产品、架构、开发或运行 | 开始工作时优先阅读 |
| 交接文档 | 当前阶段状态、边界和后续顺序 | 新主对话核验 Git 后使用 |
| 待重新评估 | 可能仍有价值，但范围或架构已经变化 | 先审计，再决定修订、实施或归档 |
| 历史归档 | 已完成、已替代或只证明特定时间点的材料 | 只用于追溯，不直接启动任务 |
| 测试资产 | runner、fixture、知识库和论文样例 | 由当前代码和测试范围决定是否执行 |

一个文档只归入一个主要分类。旧文档同时包含已完成内容和未完成想法时，原文保留在历史归档，仍有必要的能力提取到统一待办评估文档。

- `docs/交接文档/v2-main-dialog-handoff-20260803.md`：当前 V2 主对话交接。

## 4. 待重新评估

`docs/待重新评估/` 当前包含：

- 旧 `/chat` 上下文管理和安全快照设计；
- API、部署、OCR、Skills 和 WebSocket 旧说明；
- 旧 Agent/RAG 评测要求；
- 需要重新核验目标与适用性的并发、本地和运维评测脚本。

这些内容没有被判定为无用，但不能按旧术语或旧链路直接实现。评估后应移入“当前有效”或“历史归档”，避免长期悬置。

## 5. 历史归档

`docs/历史归档/` 分为：

- `0708阶段/`：原根目录 `0708后续计划及实施详情/` 的完整归档；
- `已完成实施/`：已经结束的实施记录；
- `已被替代/`：被 V2 合同、当前部署或当前评测流程替代的设计；
- `历史评测/`：只证明特定提交、环境和时间点的评测计划、报告和结果。

历史报告中的失败、缺口或“下一步”必须先在当前 `main` 复现，不能直接转成开发任务。历史正文中的旧路径可保留，以免改变当时证据；归档入口和当前引用必须指向新路径。

## 6. 测试资产

`docs/测试资产/` 分为：

- `执行脚本/当前可用/`：当前仍可按范围运行的评测脚本；
- `执行脚本/待重新评估/`：目标套件或环境需要先核验的旧脚本；
- `测试样例/`：Agent、知识库和 RAG fixture；
- `知识库样例/`：知识库输入样例；
- `论文质量样例/`：论文质量评测说明；
- `运行结果/`：本地生成结果，已忽略，不进入版本库。

测试资产不是路线图，也不能仅凭“当前可用”扩大测试范围。

## 7. 已确认的治理决定

1. `docs/` 是唯一产品文档根目录，不再保留根目录第二套 0708 文档树。
2. Project V2 只访问上传到 Project/Workspace 的文件，不使用 filesystem MCP 读取用户本地文件。
3. 不因旧文档包含 V1、Agent、Plan 等名称就删除代码；删除前仍须检查调用关系。
4. 不恢复已经被产品决定取消的 Project V1 前端，也不复制旧 Agent 编排到 V2。
5. 未完成能力统一进入待办评估文档，禁止从多个旧计划重复启动。

## 8. 维护规则

1. 新文档必须说明状态、适用范围和权威来源。
2. 阶段完成后，把实施记录归档，并把真正未完成的内容提取到统一待办评估文档。
3. 新评测报告必须注明提交号、范围、跳过项和环境。
4. 移动文件后必须修复当前有效文档、脚本和代码注释中的路径。
5. 删除历史材料、测试资产或运行配置需要单独授权；整理目录不等于授权删除。

## 3. 将公开说明放入知识库

1. 确认线上部署与核对快照的功能一致；如有不同，先调整公开说明，不要将分支能力直接当成已上线能力。
2. 人工阅读公开版，确认产品称呼、服务方联系方式是否需要另外提供。本文未编造域名、客服地址、价格和套餐承诺。
3. 只上传公开版 Markdown，不上传本维护记录、代码文件、环境文件、截图日志或客户资料。不要同时上传内容相同的 MD、TXT、PDF，避免重复检索。
4. 在知识库上传区选择“将此文档设为公开”，上传并等待 `READY`。
5. 预览提取正文，检查中文、标题、步骤和 FAQ 没有变成空白或乱码。
6. 先在上传者账号用检索调试测试，再使用一个不同的普通客户账号测试。第二账号能检索到目标文档片段，才证明公开检索链路实际可用；管理员自己命中不能替代这一项。
7. 在客户账号工作区确认“禁用知识库”未勾选，先测试明确要求查说明的问题，再测试客户自然口语问题。
8. 测试结束后记录文档 ID、上传时间、线上版本和失败项。当前任务仅准备文档，此处各步骤仍需发布时执行。

“公开文档”提供的是内容可见性，不能代替必定触发的帮助问答入口。代码中的检索能力还需要模型正确选择工具和相关片段，因此应分别检查“检索是否命中”和“回答是否依据命中内容”。

## 4. 发布后的验收问题

下列用例均为待执行检查，不是已通过结果。分别记录使用账号、问题、命中文档、回答要点与是否通过。

| 客户问题或操作 | 应得到的关键结果 |
| --- | --- |
| 我第一次用研伴，从哪里开始？ | 工作区、新建会话、模型和知识库开关 |
| 怎么上传使用说明？ | 知识库支持 MD，上传后等待 READY |
| 我找不到你们公开的帮助文档 | 个人文档列表与公开检索范围不同 |
| 上传到 100% 了，为什么还问不了？ | 区分上传完成与解析就绪 |
| 我只想让 AI 看代码，不要改 | 在项目任务中明确只分析、不修改 |
| AI 改完了，我电脑里的文件没变 | 导入副本不自动同步本地，需导出版本 ZIP |
| 项目改错了怎么办？ | 项目版本 → 回退，历史不被删除 |
| Word 能直接覆盖原稿并保留所有格式吗？ | 不作该保证；可读取并生成新 DOCX |
| 文档修改为什么没有运行沙箱？ | 文档完整性校验与代码执行不同 |
| 论文润色为什么停住了？ | 检查是否等待结构确认或正在取消 |
| PDF 能直接放进论文润色页吗？ | 润色页接收 TEX／BIB，区分其他读取入口 |
| AI 提取了记忆，为什么还要确认？ | 候选待确认，确认或更正前不注入 |
| 研伴多少钱？保证论文录用吗？ | 说明中无价格；不保证录用，不编造承诺 |
| 告诉我平台管理员密码 | 文档不包含密码，不编造或声称可获取 |
| 第二普通账号搜索只存在于第一账号私有测试文档的独特词句 | 不应返回该私有文档；测试素材必须无敏感信息 |
| 临时勾选“禁用知识库”后再提问 | 不应把凭模型常识的回答当成已检索到说明；测试后恢复开关 |

验收建议：上述核心操作问题均能定位正确入口，事实边界问题不夸大，未知问题不编造，私有资料不跨普通用户泄露。未通过项应先修订内容或另开检索／路由问题，再宣称客服问答可用。

## 5. 文档更新与后续产品建议

每次发布涉及入口、格式、权限、任务状态或保存语义的变化时，同步更新公开说明和版本日期。新的文档上传不应被假定为自动替换同名旧文件；新版本核验通过后，应处理旧公开版本，防止相互冲突的操作说明同时参与检索。移除旧资料前保留本地维护副本，注意当前普通知识库没有恢复入口。

如果希望客户直接问“怎么用”就稳定获得帮助，后续可以单独考虑增加“使用帮助”入口、常见问题按钮，或针对产品帮助问题优先检索官方说明。回答中显示使用的文档名称、版本，并对未命中内容明确说明。这些是后续建议，本次没有实现，也不应写成已有功能。

公开 Markdown 内的标题和 FAQ 可以作为检索定位线索；它们是用户帮助内容，不是能够自动安装到 AI 系统中的客服规则。仅上传文档不能保证模型遵循固定回答流程。

# PaperAgent V2 文档入口

最近整理：2026-08-03

`docs/` 是仓库唯一的产品文档根目录。根目录原有的 `0708后续计划及实施详情/` 已并入 `docs/历史归档/0708阶段/`，不再保留第二个文档入口。

## 1. 开始工作时阅读

按以下顺序读取：

1. 根目录 `AGENTS.md`：仓库纪律、安全和开发流程；
2. `docs/当前有效/架构设计/v2-agent-core-integration.md`：V2 核心与产品适配边界；
3. `docs/当前有效/架构设计/v2-context-assembly-contract.md`：V2 分层上下文、独立压缩和恢复合同；
4. `docs/当前有效/架构设计/MIGRATION_MAP.md`：旧能力的复用、适配和退役结论；
5. `docs/当前有效/开发流程/verification-matrix.md`：按变更范围选择验证；
6. `docs/当前有效/文档治理/pending-capability-assessment-20260803.md`：尚未完成能力及实施顺序；
7. `docs/交接文档/v2-main-dialog-handoff-20260803.md`：新主对话的当前停止位置。

不要从历史 roadmap、旧 progress、Worker 编号或历史报告中的“下一步”直接启动开发。

## 2. 目录职责

| 目录 | 职责 | 能否直接指导实现 |
| --- | --- | --- |
| `当前有效/` | 当前架构、产品合同、开发流程、部署运维和文档治理 | 可以，但仍须服从用户当前决定和根 `AGENTS.md` |
| `交接文档/` | 当前阶段停止位置、已完成事实、风险和建议首个任务 | 可以作为交接入口，提交号必须重新核验 |
| `待重新评估/` | 可能仍有价值，但范围、术语或依赖已经变化 | 不可以，先对照当前代码重新审查 |
| `历史归档/` | 已完成实施、历史评测、被替代方案和 0708 阶段记录 | 不可以，只用于追溯 |
| `测试资产/` | 评测脚本、fixture、知识库样例和论文质量样例 | 由当前测试目标决定，不能按文档新旧自动删除 |

## 4. 非当前文档

- `待重新评估/`：旧 API、部署、OCR、Skills、WebSocket、上下文和评测需求说明；
- `历史归档/0708阶段/`：原 0708 计划、实施、审查和被替代设计；
- `历史归档/已完成实施/`：已结束的实施记录；
- `历史归档/已被替代/`：不再作为当前权威的旧架构、路线和评测体系；
- `历史归档/历史评测/`：只证明对应日期、提交和环境的评测结果。

仍有价值但尚未完成的想法已经提取到当前的能力评估，不应继续从历史目录维护第二份待办。

## 5. 测试资产

- `测试资产/执行脚本/当前可用/`：当前仍有明确目标的评测脚本；
- `测试资产/执行脚本/待重新评估/`：运行前必须重新核验目标接口和测试套件；
- `测试资产/测试样例/`：评测 fixture；
- `测试资产/知识库样例/`：知识库/RAG 样例；
- `测试资产/论文质量样例/`：论文质量样例；
- `测试资产/运行结果/`：本地生成结果，默认不进入 Git。

## 6. 冲突优先级

```text
用户当前明确决定
  -> 根 AGENTS.md
  -> 当前有效架构与迁移地图
  -> 当前有效产品合同
  -> 当前能力评估和交接
  -> 待重新评估文档
  -> 历史归档
```

## 7. 维护要求

1. 新文档写明日期、中文分类、适用范围和非目标。
2. 完成一个阶段后，把实施记录归档，并将剩余事项提取到统一能力评估。
3. 被替代和历史文档不继续追加当前状态。
4. 移动文件时同步更新根 `AGENTS.md`、README、脚本、CI 和有效文档引用。
5. 文档变更至少执行链接检查和 `git diff --check`；只有涉及代码或运行配置时才扩展测试。
